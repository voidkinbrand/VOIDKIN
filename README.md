# VOIDKIN — FILE 001

Multipage mobile-first storefront for VOIDKIN. Bureaucratic filing-system styling with an unsettling editorial layer. All product imagery originates from the supplied reference photos and flat sketches; photo crops are derived from those files.

## Pages

- `/index.html` — hero, collection, three Case Files, mailing-list concept.
- `/shop.html` — catalog with type and color filters, model/flat toggle.
- `/products/{slug}.html` — five physical product-page URLs, each with galleries, sizes, size table and related items.
- `/cart.html` — local draft bag with quantity changes/removal.
- `/checkout.html` — **demonstration only**. The final button produces a local on-screen preview, not a submitted order. No personal data is sent or stored.
- `/case-files.html` — print stories, case register.
- `/about.html` — manifesto.
- `/contact.html`, `/shipping-returns.html`, `/faq.html` — information pages.

## One editable catalog file

All item names, descriptions, images, prices, sizes, status and size chart placeholders live in **`data/products.json`**. The site reads this file at runtime. No duplicate prices are stored in JavaScript. `pricePlaceholder: true` displays an asterisk to make uncertainty visible. `available: null` means unconfirmed availability, not in stock.

### Updating a product

Edit the relevant product object in `data/products.json`:

- `name`, `displayName`, `concept`, `caseText`, `filedUnder`: copy.
- `price`, `pricePlaceholder`, `available`: commercial data (placeholder until confirmed).
- `sizes`, `sizeChart.rows`: size labels and measurements. Use numeric `null` for missing data.
- `model`, `flat`, `gallery`: images. When `model` is `null`, the catalog's on-model view falls back to flat sketches.

The five product-page HTML wrappers are generated by `python scripts/build_pages.py`. The names and prices displayed in browser are **loaded from JSON**, so changing those fields does not require regenerating HTML. If changing slugs or adding/removing products, update the generator and run it again. Do not add new products without brand approval.

## Production / Vercel

The application is a static site with no dependency installation or build step. Import this repository with Vercel Framework Preset **Other** and output directory set to the repository root. The files in `assets/` and `data/` are served as static assets.

The previous Telegram backend is deliberately not connected to this design prototype. `checkout.html` is a **mock**, as requested, and does not send orders, payment requests or personal information. Before selling, verify catalog details and wire an order backend securely, without committing the Telegram token. Do not launch real orders until seller identity, shipping policy, returns, and privacy notices are complete.

## Branding status

The final figurative **VOIDKIN** wordmark SVG and handwritten **oidkin** mark were not provided. Current page mastheads use typographic placeholder text; the favicon and small footer mark use a simple temporary `oidkin` word placeholder. Replace with supplied SVGs before final brand approval, preserving the intended placement.

## Photography

Original files were cropped into individual front/back views and converted into WebP at moderate quality for performance. All imagery is derived from the client's uploaded references; **no new model photos or details were generated**. If a fabric detail is unavailable, the site provides no fictional fabric macro image. All model photography has neutral gray studio backgrounds. Flat drawings are used where no on-model image exists.

## Accessibility and privacy

Semantic HTML, landmarks, skip link, alt text, high-contrast neutrals, focus indicators, reduced-motion support, button aria-pressed/expanded states and responsive layouts are included. Manual cross-device and assistive-technology QA is still recommended. Shopping bag is stored only in browser localStorage. Checkout preview data remains on the page, and disappears when closed/reloaded; newsletter form does not transmit or save email addresses.

## Local development

Serve the repository root using any static file server, e.g. `python -m http.server 8000`. Visiting the HTML files directly via `file://` will not support JSON fetching because browser file origins restrict `fetch()`.
